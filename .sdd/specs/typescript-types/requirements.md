# Documento de Requisitos

## Introdução

Este documento define os requisitos para `lib/types.ts` — o módulo central de tipos TypeScript do aplicativo companion de viagem Irlanda & UK. Os tipos modelam os dados provenientes das três abas da planilha Google Sheets (`Roteiro`, `Hospedagens`, `Transportes`) e são utilizados por todos os componentes e páginas da aplicação Next.js 14.

## Requisitos

### Requisito 1: Tipo `City` — Dados da Aba Roteiro

**Objetivo:** Como desenvolvedor do sistema, quero uma interface `City` fortemente tipada, para que todos os componentes que exibem dados de itinerário tenham acesso type-safe a cada campo da aba Roteiro.

#### Critérios de Aceitação

1. The `lib/types.ts` module shall export an interface named `City` with the following required fields: `id` (string), `cidade` (string), `emoji` (string), `data_entrada` (string), `data_saida` (string), `noites` (number), `destaque` (string), `bairro` (string), `preco_noite` (number), `moeda` (`Currency`), `atividades` (string).
2. The `City` interface `id` field shall be a unique, stable identifier generated by `lib/sheets.ts` at parse time (e.g., combining row index with city name), ensuring React list rendering has a reliable `key` prop even when the same city appears more than once in the itinerary.
3. If a `City` object is constructed with a missing required field, the TypeScript compiler shall report a type error.
4. The `City` interface shall use `readonly` modifiers on all fields to prevent accidental mutation after parsing.
5. When importing `City` from `@/lib/types`, the `lib/types.ts` module shall resolve the import without errors in TypeScript strict mode.

### Requisito 2: Tipo `Hotel` — Dados da Aba Hospedagens

**Objetivo:** Como desenvolvedor do sistema, quero uma interface `Hotel` fortemente tipada, para que a página de hospedagens e o componente `HotelCard` operem com dados estruturados e validados em tempo de compilação.

#### Critérios de Aceitação

1. The `lib/types.ts` module shall export an interface named `Hotel` with the following fields: `id` (string), `cidade` (string), `nome_hotel` (string), `data_checkin` (string), `data_checkout` (string), `noites` (number), `preco_total` (number), `moeda` (`Currency`), `status` (`HotelStatus`), `endereco` (string), `link_booking` (string | undefined), `observacoes` (string | undefined).
2. The `Hotel` interface shall mark `link_booking` and `observacoes` as optional fields, since they may be absent in some spreadsheet rows.
3. If a `Hotel` object is constructed with a missing required field, the TypeScript compiler shall report a type error.
4. The `Hotel` interface shall use `readonly` modifiers on all fields to prevent accidental mutation after parsing.
5. When importing `Hotel` from `@/lib/types`, the `lib/types.ts` module shall resolve the import without errors in TypeScript strict mode.

---

### Requisito 3: Tipo `Transport` — Dados da Aba Transportes

**Objetivo:** Como desenvolvedor do sistema, quero uma interface `Transport` fortemente tipada, para que a página de transportes e o componente `TransportCard` operem com dados estruturados e validados em tempo de compilação.

#### Critérios de Aceitação

1. The `lib/types.ts` module shall export an interface named `Transport` with the following fields: `id` (string), `tipo` (string), `emoji` (string), `origem` (string), `destino` (string), `data` (string), `horario` (string), `duracao` (string), `operadora` (string), `status` (`TransportStatus`), `preco` (number), `moeda` (`Currency`), `observacoes` (string | undefined).
2. The `Transport` interface shall mark `observacoes` as an optional field, since it may be absent in some spreadsheet rows.
3. If a `Transport` object is constructed with a missing required field, the TypeScript compiler shall report a type error.
4. The `Transport` interface shall use `readonly` modifiers on all fields to prevent accidental mutation after parsing.
5. When importing `Transport` from `@/lib/types`, the `lib/types.ts` module shall resolve the import without errors in TypeScript strict mode.

---

### Requisito 4: Tipos Literais de Status e Moeda

**Objetivo:** Como desenvolvedor do sistema, quero tipos literais union para os campos de status e moeda, para que apenas valores válidos sejam aceitos e o compilador detecte strings inválidas em tempo de compilação.

#### Critérios de Aceitação

1. The `lib/types.ts` module shall export a type alias `HotelStatus` defined as the union `'confirmado' | 'pendente'`.
2. The `lib/types.ts` module shall export a type alias `TransportStatus` defined as the union `'pago' | 'pendente'`.
3. The `lib/types.ts` module shall export a type alias `Currency` defined as the union `'EUR' | 'GBP' | 'BRL'`, covering the euro (Ireland), pound sterling (UK), and Brazilian real (purchase currency).
4. If a value not belonging to `HotelStatus`, `TransportStatus`, or `Currency` is assigned to the respective field, the TypeScript compiler shall report a type error.
5. The `Hotel` interface `status` field shall use `HotelStatus` as its type, and the `moeda` field shall use `Currency` as its type.
6. The `Transport` interface `status` field shall use `TransportStatus` as its type, and the `moeda` field shall use `Currency` as its type.
7. The `City` interface `moeda` field shall use `Currency` as its type.

---

### Requisito 5: Organização e Exportações do Módulo

**Objetivo:** Como desenvolvedor do sistema, quero que `lib/types.ts` seja o único ponto de definição de todos os tipos de domínio, para que imports centralizados evitem duplicações e inconsistências entre arquivos.

#### Critérios de Aceitação

1. The `lib/types.ts` module shall export all domain types (`City`, `Hotel`, `Transport`, `HotelStatus`, `TransportStatus`, `Currency`) as named exports.
2. The `lib/types.ts` module shall contain no `any` types.
3. The `lib/types.ts` module shall contain no business logic, data transformation, or API call code — only type and interface definitions.
4. While TypeScript strict mode is enabled, the `lib/types.ts` module shall compile without errors or warnings.
5. The `lib/types.ts` module shall not import from other project files; it shall be a leaf module with zero internal dependencies.

---

### Requisito 6: Compatibilidade com Dados Brutos do Google Sheets

**Objetivo:** Como desenvolvedor do sistema, quero que os tipos definam claramente quais campos são string versus number, para que a camada `lib/sheets.ts` possa realizar o parsing correto dos valores retornados pela API do Google Sheets.

#### Critérios de Aceitação

1. The `City`, `Hotel`, and `Transport` interfaces shall use `string` for all date and time fields (`data_entrada`, `data_saida`, `data_checkin`, `data_checkout`, `data`, `horario`), preserving the original spreadsheet format without imposing a `Date` object.
2. The `City` interface `preco_noite` field, the `Hotel` interface `preco_total` field, and the `Transport` interface `preco` field shall use `number` type, requiring the sheets parsing layer to convert raw string values before constructing the typed object.
3. The `City` interface `noites` field and the `Hotel` interface `noites` field shall use `number` type, requiring the sheets parsing layer to convert raw string values.
4. If `lib/sheets.ts` constructs a `City`, `Hotel`, or `Transport` object with a string value where `number` is required, the TypeScript compiler shall report a type error.
5. The `City` interface `atividades` field shall use `string` type, allowing `lib/sheets.ts` to decide how to split or format the comma-separated activities value.
6. The `lib/sheets.ts` parsing layer shall normalize all date string values to the `DD/MM` format as sourced from the spreadsheet, ensuring consistent ordering and display across the itinerary, accommodations, and transport pages.
